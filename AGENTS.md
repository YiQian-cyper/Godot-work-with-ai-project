# AGENTS.md

This file is for AI coding agents (Codex, etc.) working in this repository. It describes the project's conventions and gotchas.

## Teaching workflow (IMPORTANT - read first)
This project is used for teaching. When generating code, always work in small, incremental steps and teach as you go:
- Before each step, briefly state what that step will implement (its goal and the plan) and why.
- Implement only ONE step, then stop and ask the user to confirm or try it out.
- Wait for the user's confirmation before starting the next step. Do not implement multiple steps in one go.
- Keep each step small and focused so it is easy to follow and verify.
- Explain each step in Chinese (the user communicates in Chinese).

## Project overview
- Engine: **Godot 4.7** (Forward Plus); scenes use `format=3` and `config_version=5`.
- Project name: AITestGame - a 2D top-down pixel game.
- Dev environment: Windows + PowerShell.
- This repo is **not a git repository** (no `.git`), so there is no diff/rollback. Back up files before large changes.

## Directory layout
- `scences/` - scenes. **The spelling really is `scences` (not `scenes`)**; always use this exact path. Contains `player.tscn` and `world.tscn`.
- `scripts/` - GDScript files, e.g. `scripts/player.gd`.
- `sprites/` - art assets, grouped by purpose: `characters/`, `tilesets/`, `objects/`, `particles/`.
- `.godot/` - auto-generated by the engine (import cache, etc.). **Never edit by hand.**

## Player scene conventions
- `scences/player.tscn`: root `Player` (CharacterBody2D) + `CollisionShape2D` + `AnimatedSprite2D`; the script is attached to the root node (`scripts/player.gd`).
- `scences/world.tscn` references `player.tscn` as an instance.
- Character sheet `res://sprites/characters/player.png`: **288x480, 6 columns x 10 rows, 48x48 per cell.**
  - Region for frame `i`: `Rect2((i%6)*48, (i//6)*48, 48, 48)`.
- Animations in the `AnimatedSprite2D`'s `SpriteFrames` (by frame index):
  - `idle_down` (0-5), `idle_right` (6-11), `idle_up` (12-17)
  - `walk_down` (18-23), `walk_right` (24-29), `walk_up` (30-35)
  - `attack_down` (36-39), `attack_right` (42-45), `attack_up` (48-51)
  - `death` (54-56)
- This sheet only has **down / right / up** facing for each action. **Use `flip_h` to mirror for left**; there are no dedicated left-facing frames.

## Coding conventions
- Language: GDScript. Keep changes **minimal and consistent with the existing style**.
- **Do not add unrequested features** (movement, collision, state machines, etc.) unless explicitly asked.
- Communicate with the user in **Chinese**.

## Editing scenes / resource files
- When editing `.tscn`, preserve `uid`, `unique_id`, and `[ext_resource]` ids; do not reorder or delete them.
- Build frame animations from `AtlasTexture` sub-resources that reference the character sheet; keep `duration`, `speed`, and `loop` consistent with the existing style.
- Do not hand-edit `*.import` files or anything under `.godot/`; let Godot manage them.

## Local environment & validation
- Godot executable: your local Godot 4.7.2 binary, e.g. `Godot_v4.7.2-stable_win64.exe`.
- To check that a scene loads (headless): PowerShell does not wait for the Godot process, so use `Start-Process -Wait -PassThru` and redirect output.
  - Example: `godot --headless --path <project-root> --script res://<check-script>.gd`.
- `apply_patch`: in this environment, passing a multi-line patch argument through cmd/PowerShell corrupts it; prefer using Python `subprocess` to pass the patch as a **single argv** to `codex.exe --codex-run-as-apply-patch`.
- PowerShell has no bash heredoc; write scripts/files with a PowerShell single-quoted here-string or `Set-Content`.
